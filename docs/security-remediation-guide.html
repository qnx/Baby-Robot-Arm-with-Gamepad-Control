High-severity findings

H-01 — ROS/DDS actuator command plane has no enforced publisher authorization

High

Issue

The controller and IK solver use global actuator-facing topics with ordinary depth-10 subscriptions. The repository launches them without an enforced SROS2 identity or deny-by-default topic policy, so any participant that can join the DDS domain can attempt to publish motion commands.

Source and vulnerable code

src/arm_controller/src/arm_controller_node.py:148–153 src/ik_solver/src/ik_solver_node.cpp:115–121 
self.mov_subscription = self.create_subscription(JointState, '/mov', self.mov_callback, 10)
self.joy_subscription = self.create_subscription(Joy, "/joy", self.joy_callback, 10)
self.joint_subscription = self.create_subscription(JointState, "/joint", self.joint_callback, 10)

Remediation

  • Create a per-robot SROS2 keystore and a distinct enclave for the HID broker, IK solver, controller, and a single command gateway.
  • Enable DDS authentication/encryption and deny-by-default permissions. Only the gateway may publish actuator-facing commands; the controller may subscribe but not publish them.
  • Launch with fixed, root-owned security material and enforced security strategy. Put all topics in a per-robot namespace, use an assigned domain ID, and filter DDS transport at the network boundary.
  • Add one exclusive, expiring control lease and an independent physical E-stop. Namespaces and domain IDs are isolation aids, not authentication.
Why this works: DDS identity checks reject unknown participants, while topic permissions stop an authenticated but unauthorized node from writing motion topics. The lease bounds the lifetime of granted control; network isolation and E-stop provide independent containment.

Patch status and residual: the launcher now requires enforced SROS2 operation, an explicit domain ID, and a per-robot namespace; actuator topics are relative and the runtime graph is unprivileged. Site-specific identities, governance, and deny-by-default permissions are intentionally not checked in. The deployer must generate and protect them, and an epoch or namespace is not publisher authentication.

H-02 — Root launcher executes modules and setup code from user-writable search paths

High

Issue

The documented launcher is run with root privileges, inherits loader/import paths, adds a user site directory, and sources a workspace install/local_setup.bash. With an initially empty PYTHONPATH, the leading empty component also selects the current directory. A lower-privileged writer can replace setup code, an installed node, or a shadow Python/native module and gain root execution on the next launch.

Source and vulnerable code

target_scripts/start_robot.sh:22–25 target_scripts/start_robot.sh:37–39 README.md:152–153 
export LD_LIBRARY_PATH="$LD_LIBRARY_PATH:/opt/ros/jazzy/lib"
export ROS2_NODES_INSTALL="${SCRIPT_DIR}/../install"
export PYTHONPATH="$PYTHONPATH:/opt/ros/jazzy/usr/lib/python3.11/site-packages/:/data/home/qnxuser/.local/lib/python3.11/site-packages/"

if [ -f ${ROS2_NODES_INSTALL}/local_setup.bash ]; then
    . ${ROS2_NODES_INSTALL}/local_setup.bash
fi

Remediation

  • Run the ROS nodes as an unprivileged service account. Grant only a small HID/I²C broker the minimum QNX abilities and device ACLs it needs.
  • Promote tested output to a fixed root-owned, non-writable versioned prefix; never source raw workspace build output after privilege elevation.
  • Start with a clean environment and assign absolute PATH, LD_LIBRARY_PATH, and PYTHONPATH values instead of appending inherited values. Set PYTHONNOUSERSITE=1 and unset PYTHONHOME, LD_PRELOAD, and BASH_ENV.
  • Before launch, reject symlinks, non-root ownership, group/world-writable path components, and artifacts that fail a signed manifest/hash check.
Why this works: the privileged process no longer interprets files or modules writable by the runtime user, and compromise of an ordinary ROS node is no longer automatically elevated to full root authority.

H-03 — XInput axes are decoded with the wrong signedness and byte order

High

Issue

The parser describes signed 16-bit axes but combines bytes as unsigned big-endian offset-binary. A conventional centered XInput value 00 00 therefore becomes -32768 and can be normalized to full-scale motion.

Source and vulnerable code

src/joy_teleop_hiddi/src/parser.c:129–133 src/joy_teleop_hiddi/src/joy_teleop_node.cpp:158–165 
case PARSER_MODE_ANALOG1x: return (data[6] * 0x100) + data[7] - 32768;
case PARSER_MODE_ANALOG1y: return ((data[8] * 0x100) + data[9] - 32768) * -1;
case PARSER_MODE_ANALOG2x: return (data[10] * 0x100) + data[11] - 32768;
case PARSER_MODE_ANALOG2y: return ((data[12] * 0x100) + data[13] - 32768) * -1;

Remediation

  • Keep the corrected XInput decoder available for non-energized capture and parser tests, but do not bind the hardware output-enable hook or energize servos until packets captured from each exact controller/mode on QNX pass the boundary suite.
  • Decode low byte first as signed two’s-complement: combine to uint16_t, then convert values with the high bit set by subtracting 0x10000. Prefer descriptor-derived logical limits where HIDDI exposes them.
  • Validate the exact report ID, header, length, and framing before parsing. Normalize the signed values by 32768.0, clamp to [-1, 1], and invert each axis in one named mapping layer.
  • Add packet tests for center 00 00 → 0, maximum ff 7f → 32767, minimum 00 80 → -32768, plus captured F310/F710 reports.
Why this works: signed little-endian reconstruction maps neutral to zero instead of maximum motion. Schema validation prevents another report shape from being interpreted as axes, and captured boundary tests make the byte-order contract regression-proof.

H-04 — Controller loss indefinitely replays the last motion command

High

Issue

A timer republishes cached joystick state with a new timestamp every 20 ms. Device removal detaches reports but does not clear that state, so unplugging or losing the wireless controller while a stick is deflected can continue incrementing targets indefinitely.

Source and vulnerable code

src/joy_teleop_hiddi/src/joy_teleop_node.cpp:99–109 src/joy_teleop_hiddi/src/joy_teleop_node.cpp:240–246 
joy_msg.header.stamp = this->get_clock()->now();
joy_msg.axes.assign(latest_axes_.begin(), latest_axes_.end());
joy_msg.buttons.assign(latest_buttons_.begin(), latest_buttons_.end());
publisher_->publish(joy_msg);

// Removal only detaches; cached values remain.
hidd_reports_detach(conn, inst);

Remediation

  • Track the active device, connection state, HID receipt timestamp, and monotonic last-valid-report time under the same lock as joystick state.
  • On active removal, report-stream loss, an invalid active report, or a report gap beyond the tested 250 ms bound, atomically clear every axis/button and irreversibly latch that broker process as terminal.
  • Establish a neutral final command state while holding the same publication-order lock used by the timer; orderly teardown may repeat neutral, but after the latch every queued or in-flight fresh report is discarded so depth-one DDS history cannot replace revocation with a later held-dead-man sample.
  • Shut down and exit nonzero so the launcher stops every member of the control unit. Require a fresh supervised start rather than reacquiring a controller in the faulted process.
  • For ordinary accepted reports, preserve the physical receipt timestamp rather than inventing freshness at the 50 Hz publication tick.
  • At the actuator consumer, independently reject stale/future commands, require a continuously held dead-man control, and process a valid dead-man release before parsing any other button chord.
Why this works: controller/report loss becomes a bounded, terminal source failure. Serializing the last neutral against all normal publications and forbidding any later fresh sample keeps DDS KeepLast(1) coalescing from erasing revocation. Nonzero exit lets launcher supervision disable the actuator process too, while the consumer's own age and held-dead-man checks still cover a hung broker or an undelivered final neutral.

Patch status and residual: the broker now uses physical report timestamps, depth-one publication, a 250 ms monotonic watchdog, an irreversible terminal gate, final-neutral ordering, and nonzero supervised exit for active-input faults. The neutral is best-effort DDS traffic, so actuator-side expiry and the normally-off hardware output hook remain mandatory.

H-05 — Non-exclusive HID report attachment permits silent local report takeover

High

Issue

The report is attached with flags 0. Under HIDDI’s attachment behavior, another local client can become the report recipient without this node noticing; combined with H-04, the last motion state can then replay.

Source and vulnerable code

src/joy_teleop_hiddi/src/joy_teleop_node.cpp:192–201 
if (hidd_report_attach(conn, inst, report_inst, 0, sizeof(void*), &report_handle) == EOK) {
    void **user_data_slot = static_cast<void**>(hidd_report_extra(report_handle));
    if (user_data_slot) { *user_data_slot = inst; }
    return 0;
}

Remediation

  • Attach with HIDD_REPORT_EXCLUSIVE and retain the returned report handle in a managed context.
  • Treat EBUSY, detach failures, missing extra storage, or watchdog-detected delivery loss as terminal source faults that publish a final neutral and exit nonzero.
  • Restrict HIDDI service/device access so only the small joystick broker can attach; the actuator process should not have HID access.
Why this works: exclusive attachment makes a later client fail visibly instead of silently stealing delivery. OS permissions reduce who can attempt takeover, and the freshness watchdog covers loss modes that exclusivity alone cannot detect.

H-06 — VID/PID allowlisting is treated as device authentication

High

Issue

Four spoofable USB VID/PID pairs select a parser, after which the first attachable report is trusted without checking desktop/gamepad usage, report identity, exact layout, button count, or logical ranges. A USB gadget, virtual HID, or wrong same-ID device can supply motion reports.

Source and vulnerable code

src/joy_teleop_hiddi/src/parser.c:43–47 src/joy_teleop_hiddi/src/joy_teleop_node.cpp:210–229 
const struct _device_lookup_storage _device_lookup[CONTROLLER_COUNT] = {
    {0x046d, 0xc21d, prs_v046d_pc21d},
    {0x046d, 0xc216, prs_v046d_pc216},
    {0x046d, 0xc21f, prs_v046d_pc21d},
    {0x046d, 0xc219, prs_v046d_pc219}
};

Remediation

  • Treat VID/PID only as parser selection. Require Generic Desktop plus Gamepad/Joystick usage and a tested profile of report ID, exact length, framing, button count, and logical axis ranges.
  • Reject extra or ambiguous collections and validate every callback against the stored profile before committing state.
  • Bind one device number/physical port through explicit operator arming and restrict ports/HIDDI access. Product and serial strings may reduce mistakes but remain spoofable.
  • Retain a dead-man, report-age watchdog, and downstream lease because meaningful device authentication requires trusted hardware or a gateway.
Why this works: descriptor/profile validation prevents unrelated same-ID report layouts from becoming motion, while one-device ownership and OS restrictions narrow substitution paths. The design no longer mistakes public USB identifiers for cryptographic identity.

Patch status and residual: this patch implements top-level gamepad usage, report identity, exact-length/framing, per-callback context, and single-active-device checks. Full descriptor-property fingerprinting—including button counts and logical ranges—remains a QNX target release gate pending captures from genuine F310/F710 controllers. The current implementation is therefore not claimed as USB-device authentication or complete descriptor validation.

H-07 — Malformed ROS arrays crash the controller and trigger physical shutdown motion

High

Issue

Callbacks index joystick and joint arrays before proving their dimensions. For example, unequal JointState.name and position lengths raise IndexError; the exception escapes the executor and enters a shutdown path that actively centers the arm.

Source and vulnerable code

src/arm_controller/src/arm_controller_input.py:326–334 src/arm_controller/src/arm_controller_node.py:245–269 
joint_count = len(msg.name)
for joint_idx in range(joint_count):
    if msg.name[joint_idx] not in self.joint_map:
        continue
    self.controller.set_joint_rad(
        self.joint_map[msg.name[joint_idx]], msg.position[joint_idx]
    )

Remediation

  • Validate before mode checks, indexing, or mutation. Require exactly the supported joystick schema, cap serialized array sizes, require buttons in {0,1}, and require finite axes.
  • For JointState, require equal name/position lengths, a bounded joint count, known unique names, and finite positions.
  • Build a temporary validated command and apply it atomically only after the entire sample passes; keep redundant checks in individual input handlers.
  • Catch callback errors locally, throttle rejection logs, and invoke H-11’s immediate output-disable fault path rather than centering.
Why this works: no array is indexed until its shape is proven, and atomic validation prevents partial actuator updates. A malformed sample is dropped without terminating the executor or turning error handling into a new motion command.

H-08 — Non-finite and oversized numeric commands are not rejected

High

Issue

Joint and Cartesian values reach comparison, clamping, FK/IK, and PWM conversion without a finite-number gate. In Python, NaN’s comparison behavior can make nested min/max expressions select an endpoint; in C++, NaN bypasses ordinary range comparisons and can poison solver state.

Source and vulnerable code

src/arm_controller/src/arm_control.py:238–260 src/ik_solver/src/ik_solver_node.cpp:280–345 
normalized_rad = max(min(joint.max_rad, rad), -joint.max_rad) + joint.max_rad
percent = normalized_rad / (joint.max_rad * 2) * 100
return self.set_joint(joint_num, percent)

Remediation

  • At every ingress, require math.isfinite() or std::isfinite() before comparison, clamping, state mutation, FK, or IK.
  • Reject the whole sample—not merely the offending field—when a value is non-finite or outside a strict joint, Cartesian, velocity, or acceleration envelope.
  • Validate IK output before publication and independently at the actuator boundary. Require exact joint names/count/order.
  • Track the last accepted command and enforce per-cycle displacement, velocity, and acceleration ceilings.
Why this works: NaN never reaches comparison semantics that can turn it into an endpoint, and huge/infinite values cannot poison solver state. Redundant output and actuator checks contain upstream calculation faults, while slew limits bound even a valid but discontinuous command.

H-09 — IK mode removes calibrated joint limits and the solver enforces none

High

Issue

Selecting IK explicitly disables calibrated actuator limits. The LMA solver is constructed without joint-limit arrays, and the URDF’s limits are not extracted or checked. A solution can therefore satisfy an XYZ target while exceeding the safe physical joint envelope.

Source and vulnerable code

src/arm_controller/src/arm_controller_node.py:189–201 src/ik_solver/src/ik_solver_node.cpp:206–216 
case ArmControlMode.IK:
    self.active_input = self.input_ik
    self.controller.enable_position_limits(False)
Eigen::Matrix<double, 6, 1> L;
L << 1, 1, 1, 0, 0, 0;
ik_pos_solver_ = std::make_unique<KDL::ChainIkSolverPos_LMA>(kdl_chain_, L);

Remediation

  • Remove the IK call that disables limits. Make calibrated actuator bounds immutable and non-bypassable; mode-specific constraints may only narrow them.
  • Convert calibrated per-servo bounds to radians and use a joint-limited IK solver or reject every LMA solution outside those bounds.
  • Validate the seed and result for finiteness, exact joint identity, discontinuity, per-cycle delta, velocity, and acceleration. Reject malformed input before solving; if an active solve, FK, home-workspace, or publication invariant fails, exit nonzero so unit supervision fault-stops the actuator process.
  • Interpolate and validate the entire commanded path, not only the endpoint.
Why this works: a malicious target, alternate/singular IK solution, stale state, or solver defect cannot bypass the final independent constraint immediately upstream of PWM output.

H-10 — Cartesian safety boundary uses an incomplete model and performs no collision checking

High

Issue

The default KDL chain ends at Arm_03_1, before the gripper and a later revolute joint. Collision meshes referenced by the URDF are absent, and the solver only clamps one XYZ point. The physical tool or linkage can therefore leave the claimed safe region or collide while the modeled endpoint remains inside it.

Source and vulnerable code

src/ik_solver/src/ik_solver_node.cpp:36–43 src/ik_solver/config/arm5dof.urdf:163–175 
this->declare_parameter<std::string>("base_link", "world");
this->declare_parameter<std::string>("end_effector_link", "Arm_03_1");
<joint name="Revolute_1" type="revolute">
  <parent link="Arm_03_1"/>
  <child link="Gripper_Assembly_1"/>
  <limit effort="1" velocity="1" lower="-1.5708" upper="1.5708"/>
</joint>

Remediation

  • Rebuild the URDF from measured geometry so every articulated axis is in one chain; add a dedicated tool0/TCP after the complete gripper and make it the endpoint.
  • Fail startup unless expected joint count, names, axes, origins, and limits match an approved manifest.
  • Install simplified, verified collision geometry and perform self/environment collision plus swept/interpolated path checks before publication.
  • Apply workspace constraints to the tool and arm swept volume while retaining independent actuator joint limits.
Why this works: the safety calculation now represents the actual tool and full linkage. Collision-producing postures and paths are rejected even when a single endpoint coordinate lies inside its allowed box.

H-11 — Fault shutdown moves the robot before disabling outputs

High

Issue

Every exception leaving spin() reaches one shutdown routine that commands all joints to center, loops without a deadline, and disables PWM only afterward. A malformed message, I²C fault, collision, or termination signal can therefore create additional motion precisely when safe behavior should be stop-first.

Source and vulnerable code

src/arm_controller/src/arm_controller_node.py:334–344 src/arm_controller/src/arm_controller_node.py:361–367 
self.smoothing_timer.cancel()
self.controller.center_all_servos()
while not self.controller.is_servos_centered():
    self.controller.update()
    time.sleep(0.02)
self.controller.release_all_servos()
self.controller.pwm.software_reset()

Remediation

  • Split shutdown into fault_stop() and an explicitly requested park_and_stop().
  • fault_stop() must stop accepting commands and immediately assert a hardware OE/servo-power cutoff. Treat I²C FULL_OFF as best-effort secondary cleanup and never center on this path.
  • Route callback exceptions, signals, I²C errors, and supervisor failures to fault stop.
  • Allow parking only after explicit clearance confirmation, with calibrated bounds, limited velocity, a monotonic deadline, and immediate abort-to-OE on error.
Why this works: faults cannot generate a second commanded trajectory, and the safe transition neither waits on an unbounded centering loop nor depends solely on the I²C path that may already have failed.

H-12 — Actuator outputs and the three-process stack are not crash-safe

High

Issue

PWM release is software-only, channel changes require multiple I²C writes, and the launcher backgrounds three unsupervised processes. SIGKILL, interpreter abort, middleware failure, or I²C loss can leave the PCA9685 producing its last duty cycles while peer nodes remain alive.

Source and vulnerable code

src/arm_controller/src/arm_control.py:172–193 target_scripts/start_robot.sh:64–81 
if not self.pwm_outputs_enabled:
    self.pwm.enable_all_pwm()
    self.pwm_outputs_enabled = True
ros2 run joy_teleop_hiddi joy_teleop_node &

ros2 run ik_solver ik_solver_node \
    --ros-args \
    -p cart_min_limits:="${CART_MIN_LIMITS}" \
    -p cart_max_limits:="${CART_MAX_LIMITS}" &

ros2 run arm_controller arm_controller_node.py \
    --ros-args \
    -p servo_min_limits:="${SERVO_MIN_LIMITS}" \
    -p servo_max_limits:="${SERVO_MAX_LIMITS}" &

wait

Remediation

  • Wire PCA9685 OE or servo power to a normally-disabled independent watchdog/enable circuit. Require a periodic heartbeat; loss of process/host power must disable outputs.
  • On partial I²C failure, assert that independent kill line before attempting further bus cleanup.
  • Replace bare background jobs with a QNX service or ROS lifecycle supervisor that treats all three nodes as required, records PIDs, terminates peers on first failure, and performs bounded cleanup with escalation.
  • Do not allow joystick or IK nodes to survive alone with stale command authority.
Why this works: the actuator defaults off even when Python, DDS, or I²C cleanup cannot execute, while unit supervision prevents a partially failed stack from continuing to publish or retain stale actuator state.

H-13 — One command starts indefinite autonomous motion and may inherit disabled limits

High

Issue

One Start-plus-face-button sample enables an internally generated dance. While enabled, the normal inactivity check is skipped; entering from IK also preserves the disabled-limit state. A stale, accidental, or injected sample can therefore create indefinite autonomous motion outside the calibrated envelope.

Source and vulnerable code

src/arm_controller/src/arm_controller_node.py:258–270 src/arm_controller/src/arm_controller_node.py:322–330 
if self.screensaver_enabled:
    self.input_screensaver.update()
elif not self.controller.servos_are_released:
    has_timed_out = (
        time.time() - self.controller.last_input_time
    ) > self.SERVO_RELEASE_TIMEOUT_SEC

Remediation

  • Model autonomous dance as a separate safety state entered only by an edge-triggered, explicitly armed request with a short renewable lease/dead-man and hard maximum duration.
  • Always re-enable calibrated limits before entry and validate the whole trajectory against per-joint and collision constraints.
  • Evaluate lease, heartbeat, and inactivity on every cycle, including autonomous cycles; fault-stop immediately when authority expires.
  • Do not refresh operator authority when internally generated targets call set_joint().
  • On autonomous entry or dance change, autonomous cancellation, control-mode changes, and fault/disarm, freeze every queued target at the last commanded position before new authority can renew the lease. Re-arm then begins from the target already frozen by the preceding disabled state.
Why this works: a single sample cannot sustain motion, generated trajectories cannot inherit a less restrictive IK state, and losing or transferring authority cannot continue a stale trajectory from the prior state.

H-14 — Startup enables motion from an assumed center without position feedback

High

Issue

Software initializes every joint as though it were centered, then commands centering and enables PWM without sensing the arm’s real pose. After manual displacement, reset, or power restoration, startup can cause unexpected travel.

Source and vulnerable code

src/arm_controller/src/arm_control.py:81–96 src/arm_controller/src/arm_controller_node.py:167–172 
self.center = max(self.min_pos, min(self.max_pos, 50.0))
self.target = self.center
self.current = self.center + self.SMOOTHING_FACTOR
self.speed = self.SERVO_SPEEDS[joint.value]

Remediation

  • Initialize pose as unknown and keep OE/power disabled. Use an explicit DISABLED → HOMING → ARMED state machine.
  • Prefer absolute encoders or home switches. Seed the controller and planner only from a measured pose.
  • If sensing cannot be added immediately, require a manual safe-pose/clear-zone acknowledgement and use low-speed, torque/current-limited homing with a hard timeout and abort.
  • Remove unconditional startup centering and apply strict first-move slew limits.
Why this works: outputs cannot energize from a fictional pose, so restart or manual displacement does not turn the first timer tick into an uncontrolled centering trajectory.

Medium-severity findings

M-01 — Commands have no freshness, sequence, source lease, size, rate, or slew enforcement

Medium

Issue

Default queued subscriptions accept unbounded semantic command streams without owner, age, sequence, or replay checks. Joystick movement increments once per received message and IK runs synchronously per sample, making physical speed and CPU load depend on publisher behavior.

Source and vulnerable code

src/arm_controller/src/arm_controller_node.py:148–153 src/arm_controller/src/arm_controller_input.py:135–140 
self.joy_subscription = self.create_subscription(Joy, "/joy", self.joy_callback, 10)

self.controller.move_joint(JointNum.BASE, -1 * msg.axes[GamepadAxis.X.value])
self.controller.move_joint(JointNum.SHOULDER, msg.axes[GamepadAxis.Y.value])
self.controller.move_joint(JointNum.ELBOW, msg.axes[GamepadAxis.RY.value])

Remediation

  • Put a command gateway before actuators and use a bounded command type with fixed fields plus source_id, lease_id, monotonic sequence, and source timestamp.
  • Before mutation, enforce schema, maximum serialized size, finite bounded values, active lease, accepted age/future skew, and strictly increasing sequence.
  • Use KeepLast(1), short lifespan/deadline QoS, DDS resource limits, and latest-sample coalescing instead of command backlogs.
  • Apply commands only at the fixed control tick; cap displacement using monotonic elapsed time and velocity/acceleration/jerk bounds. Rate-limit rejection logs and cap IK work.
Why this works: stale, replayed, out-of-order, oversized, and non-owner samples are dropped before state changes. Coalescing and fixed-rate work bound CPU/queue effects, while slew limits keep publisher rate from becoming robot speed.

Patch status and residual: subscriptions now use depth one; Joy and actuator-facing JointState samples receive exact shape, finite/range, age/future-skew, replay, lease, and slew checks. Direct-joint entry and re-arm rotate a bounded process-lifetime epoch, announce it on relative joint_session, and require the exact joint-session:N frame in addition to the local receipt-time and source-stamp checks; zero revokes the producer session on fault or mode exit. This prevents a clock-skewed pre-grant sample from crossing a later grant. These epochs order sessions but do not authenticate publishers. IK work uses a fixed nominal step and rejects excessive callback gaps. The variable-length ROS message types remain, and the two Float64 coordination topics remain unstamped and per-command unsequenced; production still needs bounded IDL, DDS resource limits, explicit source leases/timestamps/sequences, and full velocity/acceleration/jerk policy.

M-02 — Multiple supported controllers race through one global state

Medium

Issue

Every matching device can attach, but every callback overwrites the same singleton vectors. Reports from two real or spoofed devices can interleave, and removal neither selects a remaining owner safely nor neutralizes the shared state.

Source and vulnerable code

src/joy_teleop_hiddi/src/joy_teleop_node.cpp:210–229 src/joy_teleop_hiddi/src/joy_teleop_node.cpp:154–185

Remediation

M-04 — HID callback context and teardown are not exception/lifecycle safe

Medium

Issue

The callback dereferences user_data without first checking it, attachment can report success without stored context, and teardown disconnects then destroys the mutex while leaving the static node pointer dangling. A callback anomaly or teardown race can crash or access destroyed state.

Source and vulnerable code

src/joy_teleop_hiddi/src/joy_teleop_node.cpp:142–152 src/joy_teleop_hiddi/src/joy_teleop_node.cpp:192–201 src/joy_teleop_hiddi/src/joy_teleop_node.cpp:73–77

return 0;

Remediation

  • Check callback context, stored device pointer, data pointer, report handle, flags, and verified length before dereference or parsing. Commit only a fully parsed temporary state.

  • Teardown in order: cancel timer, set stopping flag, neutralize, detach reports, disconnect, wait for in-flight callbacks to reach zero, invalidate contexts/generation, null the singleton, then destroy state.

Why this works: pointer validation and all-or-nothing commits remove null and partial-state failures. A callback barrier prevents use-after-destruction, while RAII guarantees unlock even if copying or allocation throws.

M-06 — software_reset() writes a channel register instead of issuing SWRST

Issue

M-07 — Safety timing uses adjustable clocks and IK permits oversized or negative dt

Medium

Issue

The inactivity timer uses wall time, so a clock correction can postpone or prematurely trigger release. IK integrates using ROS time and replaces only gaps greater than 0.5 seconds; rollback produces negative integration, while a near-threshold delay permits a very large motion step.
